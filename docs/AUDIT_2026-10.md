# Repository audit and production-readiness pass (2026-10-05)

A stabilization pass, not a redesign. The repository is the source of truth. Status words:
**VERIFIED (CI)** means compiled and tested in CI. **VERIFIED (local)** means run in the sandbox. **EXTERNAL VERIFICATION REQUIRED** depends on credentials, a deployment or a real phone.

## Gaps found and what was done

| # | Gap | Action | Status |
|---|---|---|---|
| 1 | `server/Dockerfile` used `VOLUME /data`, which Railway rejects at build time. | Removed `VOLUME` (mount the volume explicitly instead). Added `server/railway.json` (Dockerfile builder, `/health` healthcheck, 1 replica). The healthcheck honours `$PORT`. | Code done. EXTERNAL VERIFICATION REQUIRED (no Docker/Railway build run here). |
| 2 | Railway volumes are root-owned while the image runs as `node`. | Startup prints a clear "Cannot open database … set RAILWAY_RUN_UID=0" and exits(1), instead of crashing obscurely. Documented in DEPLOY.md §4b. | VERIFIED (local, unwritable path). |
| 3 | Shutdown did not wait for an in-flight scheduler tick and never closed SQLite. | SIGTERM/SIGINT now stops new ticks, closes the HTTP server, waits up to 10 s for the tick, then `db.close()`. Hard exit after 15 s. | VERIFIED (local boot, `/health`, SIGTERM). |
| 4 | Telegram send existed on the server but **not in the app builder** (a V1 action). | New `TelegramSendStep` (chat, message, silent). | 5 | No app UI for webhooks (the server had list/detail/enable/rotate/test/history). | New Webhooks list and detail screens: copy URL, enable/disable, generate secret (shown once), regenerate URL, send test, linked automations, recent requests linking to the run. | VERIFIED (CI compile). Production key path: EXTERNAL VERIFICATION REQUIRED. |

## Known remaining limits (not changed in this pass)

* Templates are app-side (`TemplateGallery`). The server `/v1/templates` catalogue is not surfaced in the app.
* Global search (`/v1/search`) and the audit log have server endpoints but no app screen.
* The Flutter test count isn't visible, because the CI report comment is truncated. The pass/fail status is reliable.
* Nothing is deployed. Gmail, push (FCM), password-reset email and WhatsApp Business need operator credentials (EXTERNAL CONFIG REQUIRED).
* Switching the published APK from the dev key to a production key is a **signature change**: testers must uninstall once.
